# 0.7.3 — 2026-11-22

## Added

- **`addresstype`** on each result of `openstreetmap_search_places`, `openstreetmap_reverse_geocode`, and `openstreetmap_lookup_objects` is Nominatim's address label (`state`, `county`, `city`), so a state, its counties, and a same-name city tell apart. It is present only when Nominatim sends a non-empty string, and `content[]` shows it as `**Address type:**` after the category ([#132](https://github.com/cyanheads/openstreetmap-mcp-server/issues/132)).
- **Name-search hint:** an exact `name` or `name:*` filter that matched nothing on `openstreetmap_query_nearby` or `openstreetmap_query_bbox` adds a `notice` carrying an `openstreetmap_search_places` call and an `openstreetmap_query_raw` query over the same scope, each on its own line. A box crossing the antimeridian gets the raw query alone, as a union of two boxes; a box of one square degree or more, height times width in degrees, gets the search call alone; a crossing box with a side that large gets none ([#136](https://github.com/cyanheads/openstreetmap-mcp-server/issues/136)).

## Changed

- **`openstreetmap-guide` skill** 1.2 → 1.3 for `addresstype`, whole elements, and the name-search hint.

## Fixed

- **`max_element_bytes`** on `openstreetmap_query_raw` has no default: an element arrives whole unless the caller sets it, where 0.7.2 withheld the arrays of any element over 20,000 B. With a bound set, `withheldNotice` opens with the value that returns the page whole ([#131](https://github.com/cyanheads/openstreetmap-mcp-server/issues/131)).
- **Array values in `content[]`** are escaped one item at a time and still read back as the array's JSON. Under Bun on macOS, a 60 MB `openstreetmap_query_raw` page peaks between 3.2 and 3.8 GiB escaped whole and between 1.4 and 1.6 GiB item by item.
- **`language`** rejects a list holding a part Nominatim cannot read (`en,!!`, `!!,en`, `English,en`, `fr,Chinese`), where 0.7.2 forwarded it and Nominatim used only the readable parts. A language name (`English`), a lone `!!`, a word such as `etymology` (which selected the `name:etymology` tag), and the underscore spelling of a region or script (`en_US`, `zh_Hant`) are rejected too. `EN`, `EN-US`, `es-419`, `en-001`, and `sr-latn` now work: an ISO 15924 script subtag is forwarded in OSM's casing (`sr-Latn`), other four-letter subtags such as `roa-tara` as written. A tag with an empty `-` subtag or one holding `_` (`en-`, `en-US_x`) stays accepted ([#134](https://github.com/cyanheads/openstreetmap-mcp-server/issues/134)).
- **Notices that quote caller text** (a tag chain, a `query`) on `openstreetmap_query_nearby`, `openstreetmap_query_bbox`, and `openstreetmap_search_places` render literally in `content[]`; `structuredContent.notice` keeps the raw text. The unresolved-boundary notice carries its existence query on a line of its own ([#128](https://github.com/cyanheads/openstreetmap-mcp-server/issues/128)).
- **Rejected `countrycodes`, `layer`, and `exclude_place_ids`** values are answered with a message naming the accepted form, not the validation regex; the advertised `inputSchema` is unchanged ([#133](https://github.com/cyanheads/openstreetmap-mcp-server/issues/133)).
- **`effectiveArea`** on `openstreetmap_query_bbox` reads `<ref> → no Overpass area` for a `within` ref that mapped to none, where it printed an area id or "closed way" ([#135](https://github.com/cyanheads/openstreetmap-mcp-server/issues/135)).
- **`no_coverage`** on `openstreetmap_reverse_geocode` carries a hint built from the zoom and layer sent: it names zoom 18 and, when `layer` omits `address`, the missing boundary and country layer, where it advised a lower zoom that never finds a result a higher one missed; the error's `when` covers the zoom and layers sent ([#137](https://github.com/cyanheads/openstreetmap-mcp-server/issues/137)).
- **`openstreetmap_search_places`:** the notice on an empty page after `exclude_place_ids` no longer says the query is correct, and the `notice` field description follows it.
- **`openstreetmap_search_places`:** a structured call that finds nothing gets a recovery hint built from the structured fields it sent; a free-form call keeps the declared hint.
- **`openstreetmap_search_places`:** `effectiveQuery` and the `no_results` message echo only what the request carried, so a whitespace-only `query` or structured field is left out.
- **`openstreetmap_query_raw`:** the notice for a query that matched nothing says an empty result is the answer and names the filters and bounds to check, in place of a syntax check.
- **`openstreetmap_query_bbox`:** the unresolved-boundary notice also names the serving endpoint's area data as a cause, dated when the page reports it.
- **`openstreetmap_lookup_objects`:** the not-found notice's closing sentence says an ID missing from the existence query's result is not in the endpoint's OpenStreetMap data.
- **`openstreetmap_query_raw`:** the `max_element_bytes` description says `withheldNotice` names the fetch for the first three withheld elements and `withheldElements` carries all of them.
