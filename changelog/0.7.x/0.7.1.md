# 0.7.1 — 2026-11-05

## Added

- **`effectiveArea`** on `openstreetmap_query_bbox` names the boundary a `within` ref reached by its `name`, `boundary`, and `admin_level` tags, so a mistyped ref shows ([#117](https://github.com/cyanheads/openstreetmap-mcp-server/issues/117)).
- **`areasTimestamp`** on `openstreetmap_query_nearby` reports the age of the area data behind the containment check ([#113](https://github.com/cyanheads/openstreetmap-mcp-server/issues/113)).
- **Endpoint failure log:** a failed Overpass submission that another follows logs one warning with the endpoint label, attempt, status, reason, and whether the host is cooling down ([#118](https://github.com/cyanheads/openstreetmap-mcp-server/issues/118)).
- **`request_too_long`** on `openstreetmap_search_places`: an HTTP 414 from a long `exclude_place_ids` walk fails as non-retryable `InvalidParams` with a hint to narrow the search ([#119](https://github.com/cyanheads/openstreetmap-mcp-server/issues/119)).

## Changed

- **`element_types`** defaults to `["node", "way", "relation"]` on `openstreetmap_query_nearby` and `openstreetmap_query_bbox`; pass `["node", "way"]` to leave relations out ([#114](https://github.com/cyanheads/openstreetmap-mcp-server/issues/114)).
- **`upstream_error`** on `openstreetmap_reverse_geocode` and `openstreetmap_lookup_objects` now states in its `when` that an HTTP 400 maps to `invalid_parameters`; no behavior change.
- **`OSM_OVERPASS_ENDPOINTS`** description lists the public instances a `|N` entry must never size: the FOSSGIS servers, maps.mail.ru, and overpass.private.coffee.
- **`openstreetmap-guide` skill** 1.0 → 1.1 for the new defaults, containing areas, and boundary names.

## Fixed

- **Containing areas:** `openstreetmap_query_nearby` matches a park, city, or other area containing the point at `distance_meters` 0 whatever the radius, where `around` alone missed an area whose outline lies outside it. An endpoint that refuses the area lookup is asked again without it, and the `notice` says areas containing the point were not checked ([#113](https://github.com/cyanheads/openstreetmap-mcp-server/issues/113)).
- **Search paging:** `openstreetmap_search_places` returns `nextExcludeIds` on every page with results, not only a full one, since Nominatim's relevance cutoff can fall short of `limit` with matches remaining ([#115](https://github.com/cyanheads/openstreetmap-mcp-server/issues/115)).
- **`no_results`** on `openstreetmap_search_places` names the `countrycodes`, `layer`, `featureType`, or bounded `viewbox` that was sent and tells the caller to relax it before rewriting the query ([#116](https://github.com/cyanheads/openstreetmap-mcp-server/issues/116)).
- **Nominatim network failures:** a refused connection, unresolvable host, or timeout fails as retryable `upstream_error` with its recovery hint on `openstreetmap_search_places`, `openstreetmap_reverse_geocode`, and `openstreetmap_lookup_objects`, where it surfaced with no reason ([#120](https://github.com/cyanheads/openstreetmap-mcp-server/issues/120)).
