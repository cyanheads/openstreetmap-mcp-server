# 0.7.2 — 2026-11-11

## Added

- **`tag_keys`** on `openstreetmap_query_nearby` and `openstreetmap_query_bbox` cuts each feature's `tags` to the listed keys (up to 50, matched exactly); `effectiveTagKeys` echoes them. Matching, `distance_meters`, and paging still read every tag ([#125](https://github.com/cyanheads/openstreetmap-mcp-server/issues/125)).
- **`sort_by`** on `openstreetmap_query_bbox` ranks the whole match set by a tag's numeric value before `offset` and `limit` apply; `unrankedCount` counts the features that lack the tag or carry a value that is not a plain decimal, which follow the ranked ones ([#127](https://github.com/cyanheads/openstreetmap-mcp-server/issues/127)).
- **Ref forms:** `osm_ids` and `within` accept `node/240109189`-style paths and openstreetmap.org URLs beside `N240109189`, and each `osm_ids` item advertises its pattern ([#126](https://github.com/cyanheads/openstreetmap-mcp-server/issues/126)).
- **Spelling hint:** a capitalized or spaced primary feature key or value (`amenity: "Fast Food"`) puts the lowercase, underscored spelling in `notice` on `openstreetmap_query_nearby` and `openstreetmap_query_bbox` ([#124](https://github.com/cyanheads/openstreetmap-mcp-server/issues/124)).
- **`query_unsupported`** on `openstreetmap_query_raw` when every configured endpoint lacks the attic data a `[date:]`, `[diff:]`, or `[adiff:]` query reads, or the metadata `out meta` prints ([#123](https://github.com/cyanheads/openstreetmap-mcp-server/issues/123)).

## Changed

- **`elements`** on `openstreetmap_query_bbox` states its default order: nodes, then ways, then relations, each by ascending OSM id, unranked unless `sort_by` is set ([#127](https://github.com/cyanheads/openstreetmap-mcp-server/issues/127)).
- **`limit`** on the four paged tools drops its 10,000 schema ceiling, so a value above it is served at the tool's cap with `limitNotice` instead of failing validation; the advertised `maximum` is now the safe-integer bound every integer field carries.
- **`openstreetmap-guide` skill** 1.1 → 1.2 for the new refs, `tag_keys`, `sort_by`, and `query_unsupported`.

## Fixed

- **Nominatim budget:** each `openstreetmap_search_places`, `openstreetmap_reverse_geocode`, and `openstreetmap_lookup_objects` call gets one 50 s budget covering its wait in line, attempts, and backoff, and ends as `upstream_error` when it runs out, where a hung instance held the call for about 128 s ([#121](https://github.com/cyanheads/openstreetmap-mcp-server/issues/121)).
- **Endpoints without attic data or metadata:** an Overpass instance answering a history query, or an `out meta` query, with its no-data remark is skipped for the call without a cooldown, and a call that still fails names each such endpoint and the data it lacks (`<origin>: no attic data`) ([#123](https://github.com/cyanheads/openstreetmap-mcp-server/issues/123)).
- **Overpass error remarks** read as Overpass wrote them (`&quot;` decoded to `"`), and `within` id 0 fails as `invalid_scope` before any request ([#129](https://github.com/cyanheads/openstreetmap-mcp-server/issues/129)).
- **Oversized ids:** an id above 9223372036854775807 fails before any request, as `invalid_id_format` on `openstreetmap_lookup_objects` and `invalid_scope` on `within`.
- **`within`** accepts an empty string beside the four corners.
- **`within` id precision:** an id above 2^53 reaches Overpass and `effectiveArea` with every digit, where it was rounded to the nearest double.
