# 0.3.1 — 2026-07-29

## Added

- **`OSM_OVERPASS_MAX_CONCURRENCY`** (default `2`) — caps Overpass queries submitted at once. Submissions past the cap queue locally in a FIFO instead of piling onto the endpoint; a queued caller's `ctx.signal` aborting rejects it without ever taking a slot.

## Changed

- **`openstreetmap_query_bbox`, `openstreetmap_query_nearby`, `openstreetmap_query_raw`** gain the `upstream_error` reason in their declared error contracts, and the `rate_limited` contract's `when`/`recovery` text drops the old "4 concurrent slots" claim in favor of `OSM_OVERPASS_MAX_CONCURRENCY` and the endpoint's `/api/status` slot budget.

## Fixed

- **Overpass out-of-memory remarks were misclassified as timeouts** — `OVERPASS_TIMEOUT_PATTERN` matched the `runtime error:` prefix common to every Overpass remark, so an OOM failure was served the raise-`[timeout:N]` recovery hint instead of `result_too_large`, and re-running an OOM query at a higher timeout spent another of the endpoint's slots identically. Narrowed to `query timed out|timed out`. ([#42](https://github.com/cyanheads/openstreetmap-mcp-server/issues/42))
- **Overpass's HTML throttle page was retried instead of failing fast** — the HTTP 200 + HTML-body response reached `isTransientOverpassError` with no `reason`, so it read as transient and was resubmitted up to 4 times. The throw now carries `{ reason: 'rate_limited' }`, matching `nominatim-service`, and the classifier treats it — plus a 429 with no `Retry-After` — as non-transient. ([#44](https://github.com/cyanheads/openstreetmap-mcp-server/issues/44))
- **Overpass runtime remarks outside timeout/OOM silently returned an empty success** — narrowing the timeout pattern opened a gap where a dispatcher, database, or malformed-filter remark fell through both checks and came back as a result with no elements, hiding the failure behind "no results". Any remaining remark now throws `upstream_error` with the remark verbatim. ([#41](https://github.com/cyanheads/openstreetmap-mcp-server/issues/41))

## Dependencies

- `@cyanheads/mcp-ts-core` ^0.10.17 → ^0.11.0
- `scripts/check-dependency-specifiers.ts` resynced from the framework: the strict no-floating-specifier rule now also covers `overrides`, since a floating override re-resolves the exact transitive pin the entry exists to hold.
- `bun run audit:refresh` re-resolved the lockfile; the two remaining transitive advisories (`brace-expansion`, `@hono/node-server`) have no in-range fix available and are unrelated to this release.
