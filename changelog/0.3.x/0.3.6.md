# 0.3.6 — 2026-08-02

## Changed

- **`openstreetmap_query_nearby` and `openstreetmap_query_bbox`'s advertised `inputSchema` now carries `anyOf: [{ required: ['amenity'] }, { required: ['tag_key', 'tag_value'] }]`** as a sibling of `type`/`properties`/`required`, so an argument generator reading the schema alone sees that a tag mode is required. The flat `amenity`/`tag_key`/`tag_value` fields keep their names, types, and optionality — every argument set valid under 0.3.5 stays valid. `resolveTagInput` is unchanged and remains the sole enforcement point; runtime error behavior is unchanged. ([#47](https://github.com/cyanheads/openstreetmap-mcp-server/issues/47))
- **Residual:** the advertised schema expresses "at least one tag mode," not mutual exclusivity — `amenity` sent alongside `tag_key`/`tag_value` still satisfies the schema and is rejected only at runtime, the same as before.
