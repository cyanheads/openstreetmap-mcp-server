# 0.3.5 — 2026-08-02

## Added

- **`openstreetmap_query_raw`** gains `limit`/`offset` inputs and `totalFound`/`truncated`/`nextOffset` output fields, mirroring `query_nearby`/`query_bbox`'s paging shape instead of returning every matched element unbounded. ([#50](https://github.com/cyanheads/openstreetmap-mcp-server/issues/50))

## Fixed

- **A throttled or self-diagnosed-faulty Overpass endpoint ended the call instead of failing over.** `OverpassService` now tracks such endpoints per-call and rotates to the next entry in `OSM_OVERPASS_ENDPOINTS`, failing only once every configured endpoint has refused the query. ([#49](https://github.com/cyanheads/openstreetmap-mcp-server/issues/49))
- **A non-JSON HTTP 2xx Overpass response reached `JSON.parse` and surfaced as an unclassified `SyntaxError`.** It is now classified by what the error document says — throttle or instance fault — before parsing is attempted. ([#49](https://github.com/cyanheads/openstreetmap-mcp-server/issues/49))
- **Client-side deadlines now derive from the query's effective `[timeout:N]`** instead of a flat 90s/120s pair, so `openstreetmap_query_raw`'s advertised `timeout_seconds` up to 180 is honored end to end. Both layers widen only, so `query_nearby`/`query_bbox` (capped at 60s) see no change. ([#51](https://github.com/cyanheads/openstreetmap-mcp-server/issues/51))
- **The Overpass result cache retained a multi-hundred-MB result for its full 10-minute TTL.** It now declines to cache a response past 100,000 elements, capping one cached result near 25 MB. This bounds retention, not the transient parse peak — `JSON.parse` still materializes the complete response before the ceiling applies, so a single oversized call still spikes memory for its own duration. ([#50](https://github.com/cyanheads/openstreetmap-mcp-server/issues/50))
