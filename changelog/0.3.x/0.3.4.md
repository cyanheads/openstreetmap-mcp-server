# 0.3.4 — 2026-07-29

## Added

- **`OSM_OVERPASS_ENDPOINTS`** — comma-separated ordered list of Overpass endpoints. A transient failure (5xx, HTML throttle page, connection timeout) advances `OverpassService` to the next entry within the same tool call; deterministic failures (`query_timeout`, `result_too_large`, HTTP 400) stay on the current endpoint. Defaults to the single FOSSGIS instance, so out-of-the-box behavior is unchanged — failover only activates once an operator lists a second endpoint. ([#37](https://github.com/cyanheads/openstreetmap-mcp-server/issues/37))
- **`openstreetmap_query_bbox`, `openstreetmap_query_nearby`, `openstreetmap_query_raw`** gain a `servingEndpoint` enrichment field naming the endpoint that produced the response, redacted to origin and path. A cache hit reports the endpoint that originally served the data rather than the one the reading call would try first. ([#37](https://github.com/cyanheads/openstreetmap-mcp-server/issues/37))
- **`endpoints_exhausted`** error reason on all three Overpass tools, thrown when the call's total time budget runs out before any endpoint answers.

## Changed

- **`OSM_OVERPASS_BASE_URL`** no longer carries a default value. When set, it still pins every query to that single endpoint and disables failover. When unset, `OSM_OVERPASS_ENDPOINTS` applies instead — which defaults to the same URL `OSM_OVERPASS_BASE_URL` used to default to, so unconfigured deployments see no behavior change.
- **A single Overpass tool call now stops submitting new attempts once it has spent a 120-second total budget** — the per-attempt deadline, the endpoint-slot queue wait, and `withRetry`'s backoff between attempts all draw from it, so the call settles one backoff past the budget at the latest. Previously the per-attempt 90s deadline multiplied across the full retry budget with no combined ceiling.
