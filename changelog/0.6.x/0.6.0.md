# 0.6.0 — 2026-10-03

**Upgrading:** `servingEndpoint` and every endpoint named in messages, `error.data.url`, and logs now read as the origin alone (`https://overpass-api.de`), so match on the origin rather than the full URL. An `OSM_OVERPASS_ENDPOINTS` entry may end in `|N`; a list without suffixes keeps its current concurrency, a `|` inside a URL must be written `%7C`, and `OSM_OVERPASS_BASE_URL` rejects a suffix at startup.

## Added

- **`|N` slot suffix on `OSM_OVERPASS_ENDPOINTS` entries** ([#92](https://github.com/cyanheads/openstreetmap-mcp-server/issues/92)). `https://mirror.example/api/interpreter|4` gives that entry four slots and lets new calls use it; an unsuffixed later entry stays failover only. A malformed suffix fails startup, and a URL listed twice keeps its first entry.
- **Cross-call host cooldown** ([#81](https://github.com/cyanheads/openstreetmap-mcp-server/issues/81)). An endpoint that refuses the connection, fails DNS, or stays silent through a full attempt window is skipped by later calls for 30 s, doubling up to 10 min, then probed by one call; any HTTP response clears it. Error messages mark such an endpoint `(cooling down)`.
- **Identical in-flight queries share one submission** ([#89](https://github.com/cyanheads/openstreetmap-mcp-server/issues/89)), per tenant. A caller that cancels detaches without ending it for the rest.
- **`endpoints_rejected` on the three Overpass tools** ([#87](https://github.com/cyanheads/openstreetmap-mcp-server/issues/87)). A call every endpoint refused by HTTP status (401, 403, 404, 501, a redirect) ends on this declared reason (`ServiceUnavailable`, not retryable) with each endpoint's status in the message, replacing the bare status error.
- **`pacer_shed` on the three Overpass tools** ([#90](https://github.com/cyanheads/openstreetmap-mcp-server/issues/90)). A call waits at most 30 s in total for slots, then fails `RateLimited` with a `retryAfter` of at least 30 s.

## Changed

- **Endpoints are named by origin alone** ([#91](https://github.com/cyanheads/openstreetmap-mcp-server/issues/91)) in `servingEndpoint`, cached `servedBy`, `error.data.url`, composed messages, and the retry log line; two entries on one origin read `(entry N)`.
- **`OSM_OVERPASS_MAX_CONCURRENCY` is a per-endpoint cap** for the pin and every unsuffixed entry; with no `|N` entry it still bounds the queries in flight across the whole list.
- **A call keeps one place in line** through retries and failover, and moves to an endpoint it has not tried yet without a backoff.
- **mcp-ts-core `^0.13.6` → `^0.13.10`**: error envelopes carry `data.requestId` and `content[]` closes with `request <id>` ([cyanheads/mcp-ts-core#576](https://github.com/cyanheads/mcp-ts-core/issues/576)); a declared `recovery` hint reaches the wire without `ctx.recoveryFor` ([cyanheads/mcp-ts-core#579](https://github.com/cyanheads/mcp-ts-core/issues/579)); server stack traces no longer reach clients through error data ([cyanheads/mcp-ts-core#519](https://github.com/cyanheads/mcp-ts-core/issues/519)); the MCP SDK moves to `^2.1.0`.
- **Opt-in framework logging** in `.env.example`: `LOG_TOOL_FAILURE_PAYLOADS` / `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES` ([cyanheads/mcp-ts-core#291](https://github.com/cyanheads/mcp-ts-core/issues/291)) and `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` ([cyanheads/mcp-ts-core#547](https://github.com/cyanheads/mcp-ts-core/issues/547)).
- **Docker image** installs production dependencies in a `deps` stage on the build platform, so multi-arch builds no longer run Bun under QEMU ([cyanheads/mcp-ts-core#575](https://github.com/cyanheads/mcp-ts-core/issues/575)); `MCP_FORCE_CONSOLE_LOGGING` is no longer set.
- **Documentation and tooling, no runtime change:** the README is condensed around the current surface; `docs/design.md` records this release's decisions; the framework skills and `scripts/` are synced to mcp-ts-core 0.13.10; `.mcpbignore` excludes `docs/idea.md` and `logs/`, and `package.json` `files` excludes `dist/*.mcpb`.

## Fixed

- **An invalid `OSM_*` variable fails startup** ([#97](https://github.com/cyanheads/openstreetmap-mcp-server/issues/97)) with the configuration banner naming it, on stdio and HTTP, instead of the server reporting ready and failing every tool call.
- **Redirects are never followed** ([#93](https://github.com/cyanheads/openstreetmap-mcp-server/issues/93)). A keyed provider's 3xx counts as the host refusing the call rather than reading as `rate_limited`, and a 307/308 no longer re-posts the query to the host `Location` names.
- **HTTP 408 and 425 carry a declared reason** ([#95](https://github.com/cyanheads/openstreetmap-mcp-server/issues/95)): 408 as `overpass_gateway_timeout`, 425 as `overpass_unavailable` (`ServiceUnavailable`), without the captured body.
- **HTTP 501 fails over** ([#98](https://github.com/cyanheads/openstreetmap-mcp-server/issues/98)) to the next endpoint instead of ending the call; a list every entry answers 501 ends on `endpoints_rejected`.
- **A cancel during the retry backoff ends as `RequestCancelled`** ([#96](https://github.com/cyanheads/openstreetmap-mcp-server/issues/96)), not a raw `AbortError`.

## Security

- **An API key in an endpoint's path or query no longer reaches responses or logs.** Beyond origin-only names, upstream text that quotes a configured endpoint's path, query string, or userinfo verbatim has each replaced with `…` ([#94](https://github.com/cyanheads/openstreetmap-mcp-server/issues/94)); a key the upstream echoes in another form (alone, or re-encoded) is not recognized.
