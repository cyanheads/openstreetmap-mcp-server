# 0.4.7 — 2026-09-10

## Changed

- **Overpass endpoint rotation** now faults a host for the rest of the call on a refused or unresolvable connection, or an attempt that goes unanswered inside its full window — not only on a throttle or an instance fault. A host that sheds load with a 5xx is still retried ([#67](https://github.com/cyanheads/openstreetmap-mcp-server/issues/67)).
- **`endpoints_exhausted`** now means "every endpoint tried was still unanswered," not only "the total budget ran out." A new **`endpoints_unavailable`** reason (`ServiceUnavailable`, retryable) covers a refusal, an unreachable host, or any mixed fault set, declared on `openstreetmap_query_raw`, `openstreetmap_query_nearby`, and `openstreetmap_query_bbox`. Both messages name each endpoint and its outcome ([#67](https://github.com/cyanheads/openstreetmap-mcp-server/issues/67)).
- **`openstreetmap_query_raw`** now accepts whitespace inside `[out:json]`/`[timeout:N]` (`[out: json]`, `[ timeout : 15 ]`) — keywords stay case-sensitive — anchors the injected timeout on the matched directive, and no longer double-injects a caller-supplied timeout in any spacing or digit width. `deriveQueryBudget` shares the same pattern, so a spaced timeout up to 99999 seconds now widens the client wait budget instead of falling back to the flat one ([#68](https://github.com/cyanheads/openstreetmap-mcp-server/issues/68)).

## Fixed

- **`countrycodes`** on `openstreetmap_search_places` is now a schema pattern (ISO 3166-1 alpha-2, any casing, tolerant of spaces and empty list elements). Nominatim silently discards a value it can't parse and answers unfiltered, so an alpha-3 code, a semicolon list, or a country name now fails validation instead of widening the search ([#66](https://github.com/cyanheads/openstreetmap-mcp-server/issues/66)).
- **`no_results`** on `openstreetmap_search_places` now echoes the full structured query — a `street`-, `county`-, or `postalcode`-only search no longer reports `No places found for ""` ([#69](https://github.com/cyanheads/openstreetmap-mcp-server/issues/69)).
