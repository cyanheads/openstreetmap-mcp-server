# 0.4.2 — 2026-08-25

## Added

- **Cache hints on the list operations** — `tools/list`, `prompts/list`, `resources/list`, `resources/templates/list`, and `server/discover` advertise `ttlMs: 3_600_000` with `cacheScope: 'public'`. The advertised surface is fixed at startup, so a redeploy is the only thing that changes any of those answers. Protocol revision 2026-07-28 only.
- **`MCP_SESSION_MODE` in `.env.example` and the README config table** — `stateless`, `stateful`, or `auto` (default `auto`, which resolves to `stateful`). This server holds no per-session state, so the published Docker image runs `stateless`.
- **`.github/CONTRIBUTING.md` and `.github/CODE_OF_CONDUCT.md`.**

## Changed

- **Tool arguments are strict.** An argument key a tool does not declare is rejected by name instead of being silently stripped, and every `inputSchema` advertises `additionalProperties: false`. A client passing an undeclared extra key now gets a validation error where the call previously ran.
- **Advertised schemas are JSON Schema 2020-12**, not draft-07, and each tool's `outputSchema` declares the failure envelope — success fields become optional and `error` is declared. A client that validates `structuredContent` without checking `isError` stops rejecting error results with `-32602`.
- **The `anyOf` requirement blocks survive the strictening.** `openstreetmap_search_places`, `openstreetmap_query_nearby`, and `openstreetmap_query_bbox` declare `.strict()` ahead of `.meta()`, so the advertised query/address and tag-mode requirements still reach the wire.
- **Argument-validation failures read as flat `path: message` sentences**, not a serialized `ZodIssue[]` blob behind an `MCP error -32602:` prefix.
- **`ctx.log` output reaches the client** as `notifications/message` at its RFC 5424 level, gated by the client's `logging/setLevel`.
- **`transport.sessionMode` on the landing page and `/.well-known/mcp.json` reports the mode the server runs in**, never `auto`.
- **Bun pins move to `1.4.0`** — both `Dockerfile` stages and `packageManager`; `engines.bun` stays `>=1.3.0`. The build stage carries `--platform=$BUILDPLATFORM`, without which Bun 1.4.0 aborts under QEMU and fails the `linux/amd64` leg of a multi-arch publish from an arm64 host ([mcp-ts-core#370](https://github.com/cyanheads/mcp-ts-core/issues/370)).
- **The production image omits optional peers** — `--omit=peer` on the production install and the OTEL add, so the framework's opt-in tiers stay out of the runtime image.
- **`tsconfig.json` typechecks `tests/` alongside `src/`** (`rootDir: "."`, `noEmit: true`); `tsconfig.build.json` carries the emit path.
- **Security reports route to `security@caseyjhand.com`.**

## Fixed

- **A cancelled Overpass call fails with a named error.** `openstreetmap_query_nearby`, `openstreetmap_query_bbox`, and `openstreetmap_query_raw` check `ctx.signal` before the cache read, so an already-aborted caller gets `OverpassSlotAborted` rather than a bare `AbortError` naming neither the service nor the query.
- **`scripts/tree.ts` honors directory-only gitignore patterns**, so `docs/tree.md` no longer lists a directory its own footer says is ignored.
