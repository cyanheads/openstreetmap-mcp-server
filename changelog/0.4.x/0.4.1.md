# 0.4.1 — 2026-08-09

## Added

- **`tagSelectionCaveat` enrichment field** on `openstreetmap_search_places` (every successful response), and on `openstreetmap_reverse_geocode` / `openstreetmap_lookup_objects` (when the call requested `extratags`), disclosing that OSM attribute tags decorate the matched or looked-up object and never select it — pointing to `openstreetmap_query_nearby`, `openstreetmap_query_bbox`, and `openstreetmap_query_raw` for tag-based selection or enumeration. ([#52](https://github.com/cyanheads/openstreetmap-mcp-server/issues/52))
- **`openstreetmap_search_places`'s query / structured-address requirement is advertised in the published `inputSchema`** as an `anyOf` over seven required-sets (`query`, `street`, `city`, `county`, `state`, `country`, `postalcode`), closing a previously-valid call with no arguments at all. Every field definition stays in root `properties`; the branches carry `required` only, since a branch declaring its own fields drops arguments in flight under at least one OpenAPI converter. ([#57](https://github.com/cyanheads/openstreetmap-mcp-server/issues/57))

## Changed

- **Tool descriptions and `extratags` field descriptions on `openstreetmap_search_places`, `openstreetmap_reverse_geocode`, and `openstreetmap_lookup_objects`** now name how each tool selects its object (name/address relevance, coordinate proximity, or an explicit ID list) and that `extratags` decorates whatever object is selected rather than steering the selection. ([#52](https://github.com/cyanheads/openstreetmap-mcp-server/issues/52))
- **`openstreetmap_search_places`'s truncation notice names the `exclude_place_ids` walk and the 40-result Nominatim ceiling**, replacing the framework's default "raise the cap or narrow with filters" guidance, whose remedies cannot reach the rest of a Nominatim result set. ([#55](https://github.com/cyanheads/openstreetmap-mcp-server/issues/55))
- **`docs/design.md`'s five Zod 3 single-argument `z.record(...)` schema snippets** are corrected to the two-argument Zod 4 form, and three drifted `.describe()` strings realigned to the shipped source. ([#58](https://github.com/cyanheads/openstreetmap-mcp-server/issues/58))
