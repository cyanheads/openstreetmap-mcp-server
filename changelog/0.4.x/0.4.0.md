# 0.4.0 — 2026-08-10

## Changed

- **`openstreetmap_search_places`'s `invalid_input` reason splits into `conflicting_query_mode` (query and structured fields both provided) and `missing_query_mode` (neither provided)**, so a caller who supplied neither mode no longer gets a "not both" recovery hint under a message telling them to supply one. ([#56](https://github.com/cyanheads/openstreetmap-mcp-server/issues/56))
- **`element_types` on `openstreetmap_query_nearby` and `openstreetmap_query_bbox` requires at least one entry**, published as `minItems: 1` in the advertised `inputSchema`. An empty array previously built a degenerate Overpass union that could only match nothing and reported the result as a geographic miss; the field keeps its `['node', 'way']` default. ([#54](https://github.com/cyanheads/openstreetmap-mcp-server/issues/54))
- deps: `@cyanheads/mcp-ts-core` ^0.11.0 → ^0.11.1

## Fixed

- **A non-JSON Nominatim 2xx body is classified instead of reaching `JSON.parse` directly.** A throttle-vocabulary match still maps to `rate_limited`; every other shape — a plain-text refusal, markup behind an XML declaration, an unrelated document — now maps to `upstream_error` instead of escaping as a bare `SyntaxError` that `withRetry` read as transient, costing four submissions before surfacing with no reason or recovery hint. `isTransientNominatimError` fails fast on `upstream_error` the same as `rate_limited`, and `openstreetmap_search_places`, `openstreetmap_reverse_geocode`, and `openstreetmap_lookup_objects` all re-throw it through `ctx.fail` so the recovery hint reaches the caller. ([#53](https://github.com/cyanheads/openstreetmap-mcp-server/issues/53))
