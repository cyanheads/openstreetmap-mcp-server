# 0.5.2 — 2026-09-21

## Changed

- **Nominatim spacing and the Overpass concurrency cap run on mcp-ts-core's `createPacer`** (0.13.4, [cyanheads/mcp-ts-core#454](https://github.com/cyanheads/mcp-ts-core/issues/454)). A Nominatim call cancelled while waiting for its slot now leaves the queue at once instead of waiting for its turn; both pacers are disposed on shutdown through `createApp({ teardown })`.
- **The Overpass call budget runs on `withRetry`'s `deadlineMs`** (0.13.4, [cyanheads/mcp-ts-core#455](https://github.com/cyanheads/mcp-ts-core/issues/455)). Budget exhaustion still reports `endpoints_exhausted`; a call whose budget runs out during backoff or while waiting for a slot now ends at the budget, and a 429 whose `Retry-After` exceeds the remaining budget surfaces as `rate_limited` at once instead of being waited out.
- **The `endpoints_unavailable` entry on the three Overpass tools names HTTP refusals** (401/403/404), in both its advertised `when` text and its recovery hint.
- **mcp-ts-core `^0.13.2` → `^0.13.6`**: argument rejections carry `data.reason: "invalid_arguments"` and a `Recovery:` line listing the accepted keys (0.13.3, [cyanheads/mcp-ts-core#445](https://github.com/cyanheads/mcp-ts-core/issues/445)) — e.g. on `openstreetmap_query_bbox` with `{"bbox": …, "query": …}`: `Recovery: Unknown keys bbox, query. This tool accepts: within, south, west, north, east, amenity, tag_key, tag_value, filters, element_types, limit, offset, timeout_seconds.` A case-style key variant is rewritten and a JSON-stringified array is repaired before validation (0.13.4, [cyanheads/mcp-ts-core#452](https://github.com/cyanheads/mcp-ts-core/issues/452), [cyanheads/mcp-ts-core#234](https://github.com/cyanheads/mcp-ts-core/issues/234)); `inputSchema` is unchanged either way. Tool error text closes with `(reason <reason>)`, plus ` · retryable` / ` · not retryable` when the error declares `retryable` (0.13.5, [cyanheads/mcp-ts-core#458](https://github.com/cyanheads/mcp-ts-core/issues/458)); `structuredContent` is unchanged.
- **Documentation and comment-only, no runtime change:** the README `MCP_SESSION_MODE` default is corrected to `stateless`; `.env.example`'s framework comments are aligned with the template; the `thrownBy: 'service'` markers on service-raised tool error reasons are lint metadata only, `tools/list` is byte-identical with or without them; CLAUDE.md/AGENTS.md now say a release-review fix lands as an ordinary commit with no force-push; the framework skills and `scripts/lint-mcp.ts` are synced to mcp-ts-core 0.13.6.

## Fixed

- **A deterministic HTTP 4xx is no longer re-submitted** ([#86](https://github.com/cyanheads/openstreetmap-mcp-server/issues/86)). Nominatim, and Overpass with one endpoint, surface a 401/403/404 after one request instead of four, and a Nominatim 501, which the framework marks `retryable: false`, likewise surfaces after one. With several Overpass endpoints, a host answering such a status is rotated past for the rest of the call and never re-asked; every host refusing keeps the status error, and a refusal mixed with other endpoint faults composes into `endpoints_unavailable`.
