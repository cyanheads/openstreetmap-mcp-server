# 0.5.0 — 2026-09-16

## Added

- **`within`** scope on `openstreetmap_query_bbox` — an OSM boundary ref (`R237385`, `W13800188`) as an alternative to the four corner fields, scoping to a relation or closed way rather than its overcovering bounding box ([#71](https://github.com/cyanheads/openstreetmap-mcp-server/issues/71)). Adds `effectiveArea`/`areasTimestamp` enrichment, an `invalid_scope` error, and a chaining recipe on the `osm_id` fields of the three Nominatim tools plus `openstreetmap_query_raw`.
- **CodeQL workflow** at `.github/workflows/codeql.yml` — JavaScript/TypeScript and Actions analysis on pushes and pull requests against `main`, plus a weekly run.

## Changed

- **`lat`, `lon`, and `boundingbox`** on `openstreetmap_search_places`, `openstreetmap_reverse_geocode`, and `openstreetmap_lookup_objects` now emit JSON numbers instead of Nominatim's wire-format strings, so a coordinate read off one tool validates directly against the numeric inputs of the Overpass tools that consume it ([#77](https://github.com/cyanheads/openstreetmap-mcp-server/issues/77)). A malformed upstream coordinate now fails as `upstream_error` rather than reaching `structuredContent` as `NaN`; a whole-degree bound renders without Nominatim's zero padding (`-180` instead of `-180.0000000`).
- **`south`, `west`, `north`, and `east`** on `openstreetmap_query_bbox` are optional in the advertised `inputSchema`, which now publishes the scope and tag modes as four `anyOf` required-sets. A call carrying only part of the corner set reaches the handler and fails as `invalid_scope` instead of being refused at the schema.
