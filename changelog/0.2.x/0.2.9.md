# 0.2.9 — 2026-07-05

## Changed

- **`openstreetmap_geocode` — `query` guidance and `no_results` recovery**: the free-form `query` description now steers callers to a POI name plus city/region and warns against inserting a parent institution, campus, or building name between them — Nominatim reads commas as an address hierarchy and returns nothing on an unmatched intermediate token. The `no_results` recovery hint now names the specific fix instead of "remove constraints." ([#18](https://github.com/cyanheads/openstreetmap-mcp-server/issues/18))
- **README — `OSM_USER_AGENT` default de-drifted**: the configuration table's example value is now the placeholder `openstreetmap-mcp-server/<package version>` instead of a hardcoded version string that had gone stale (documented as `0.1.8` while the package shipped `0.2.8`). ([#17](https://github.com/cyanheads/openstreetmap-mcp-server/issues/17))
- **Skills**: vendored skill set synced to mcp-ts-core 0.10.11 (9 files); `changelog/template.md` clarifies that `security:` flags only this project's own source fixes, not dependency/transitive CVE bumps.

## Fixed

- **`openstreetmap_geocode` / `openstreetmap_reverse` / `openstreetmap_lookup` — `language` now honored**: `nominatim-service.ts` sent the Nominatim query parameter as `accept_language` (underscore); Nominatim reads `accept-language` (hyphen) and drops unknown parameters, so the requested language was silently ignored. All three call sites now send the hyphenated key. ([#19](https://github.com/cyanheads/openstreetmap-mcp-server/issues/19))
- **`openstreetmap_geocode` — `truncated` enrichment no longer fires below the requested limit**: `ctx.enrich.truncated()` is a disclosure helper that always writes `truncated: true`; the handler called it unconditionally on every response. It's now guarded to fire only when `results.length >= input.limit`. ([#15](https://github.com/cyanheads/openstreetmap-mcp-server/issues/15))
