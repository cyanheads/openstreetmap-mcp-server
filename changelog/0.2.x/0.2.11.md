# 0.2.11 — 2026-07-06

## Fixed

- **`openstreetmap_query_raw` — `content[]` now includes element coordinates and all returned elements**: `format()` renders a `Coordinates:` line for elements carrying `lat`/`lon` and no longer caps the text render at 50 elements, restoring parity with `structuredContent.elements`. ([#20](https://github.com/cyanheads/openstreetmap-mcp-server/issues/20))
- **Nominatim tools — `content[]` now includes `country_code` and `ISO3166-2-lvl4` address fields**: the shared `appendPlaceLines()` helper (used by `openstreetmap_geocode`, `openstreetmap_reverse`, and `openstreetmap_lookup`) no longer filters these keys out of the rendered address line. ([#21](https://github.com/cyanheads/openstreetmap-mcp-server/issues/21))

## Dependencies

- **`@cyanheads/mcp-ts-core`** `^0.10.11` → `^0.10.14`: skills re-synced to the framework's current docs (new `definition-invalid` lint rule, Workers DuckDB bundling guidance, `outline-on-overflow`'s flat-object output shape).
- **Supply-chain guard adopted**: `bunfig.toml` sets a 3-day `minimumReleaseAge` hold on fresh package versions (excluding `@cyanheads/mcp-ts-core`, adopted same-day) and scans installs with `@socketsecurity/bun-security-scanner`; `devcheck`'s outdated-package check recognizes rows held back by the guard instead of flagging them.
