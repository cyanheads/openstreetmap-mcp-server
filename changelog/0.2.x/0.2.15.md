# 0.2.15 — 2026-07-26

## Changed

- **`docs/design.md` error blocks resynced with the shipped tool contracts** — stale `InvalidParams` codes, the v0.2.14 `rate_limited`/`upstream_error` contracts, and `retryable` flags now match `src/mcp-server/tools/definitions/*.ts`.

## Fixed

- **`openstreetmap_query_nearby` and `openstreetmap_query_bbox` distinguish an exhausted offset from a genuine empty result**: an `offset` past the end of a non-empty match set now reports the real match count and a valid retry offset, instead of the "try a different tag/radius" notice meant for a query that matched nothing. ([#27](https://github.com/cyanheads/openstreetmap-mcp-server/issues/27))
- **`openstreetmap_geocode`'s `exclude_place_ids` paging walk reports its own exhaustion**: the terminal page previously threw `no_results` with a query-rewrite recovery hint; it now returns success with zero results and a new optional `notice` field explaining the walk is complete, while `no_results` stays reserved for a genuine first-page miss. ([#35](https://github.com/cyanheads/openstreetmap-mcp-server/issues/35))
- **`openstreetmap_geocode`'s `content[]` text no longer disagrees with `structuredContent` on `importance`**: `format()` rounded the value to three decimals for `content[]` while `structuredContent` carried the full float; the rounding is removed so both surfaces match. ([#28](https://github.com/cyanheads/openstreetmap-mcp-server/issues/28))
- **`resolveTagInput` trims `tag_key`/`tag_value` before resolution**: previously only the presence check was trimmed, so a padded value interpolated verbatim into the Overpass filter and silently matched nothing; trimming now runs before the metacharacter check. ([#36](https://github.com/cyanheads/openstreetmap-mcp-server/issues/36))
