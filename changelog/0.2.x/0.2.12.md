# 0.2.12 — 2026-07-06

## Added

- **`openstreetmap_query_bbox` / `openstreetmap_query_nearby` — optional `offset` input pages through capped result sets**: the already-fetched, ~10-minute-cached full match set is re-sliced at `offset`; `truncated` and the new `nextOffset` enrichment field reflect the new page. Pass a prior response's `nextOffset` to retrieve the next page at no extra Overpass cost. ([#24](https://github.com/cyanheads/openstreetmap-mcp-server/issues/24))
- **`openstreetmap_geocode` — optional `exclude_place_ids` input and `nextExcludeIds` enrichment field for progressive retrieval**: `exclude_place_ids` forwards comma-joined to Nominatim's own parameter of the same name; `nextExcludeIds` accumulates prior excludes plus the current page's `place_id`s, populated only when results are truncated. Best-effort, not a stable cursor — Nominatim's internal ranking can reorder slightly between calls. ([#24](https://github.com/cyanheads/openstreetmap-mcp-server/issues/24))

## Fixed

- **`openstreetmap_query_bbox` — rejects a latitude-inverted bounding box before querying Overpass**: `south > north` now throws a declared `invalid_bbox` validation error with a recovery hint, instead of a bare upstream HTTP 400. A `west > east` box (antimeridian crossing) remains valid and unaffected. ([#22](https://github.com/cyanheads/openstreetmap-mcp-server/issues/22))
